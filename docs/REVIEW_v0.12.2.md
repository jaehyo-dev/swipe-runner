# v0.12.2 확인 기록

그림은 [review/v0.12.2/](../review/v0.12.2/) (review/에는 그림만 둔다).

측정: 맥북 에어, 헤드리스 크롬 + Metal GPU, 393x852 배율 3, 터치(휴대폰 흉내). 도구 `tools/web_probe.mjs`.
고치기 전 = 배포된 v0.12.1, 고친 뒤 = 로컬 빌드. 실제 아이폰의 열·저전력 모드는 흉내 낼 수 없다 → 최종 확인은 아이폰에서.

## 1. 30Hz 자동 품질 (`fps 30j`, CPU 4배 느리게, 160BPM, 약 45초)

`30j` = rAF를 두 번에 한 번만 넘겨 30Hz + 시드 고정으로 약 4% 한 번 더 건너뛰기(66ms). 실기기(가끔 46ms)보다 가혹하다.

| | rAF 중앙/99%/최대 ms | 품질 변화 |
|---|---|---|
| v0.12.1 | 33.3 / 66.7 / 100.1 | 14.2초 → Q1(30Hz 알아챔), 33.5초 → Q2(99% 66ms > 40ms). 계속 두면 Q4까지 |
| v0.12.2 | 33.3 / 66.7 / 100.1 | 13.3초 → Q1(30Hz 알아챔), 그 뒤 그대로 |

## 2. 열 신호 오판 (고친 뒤, 열 없음, 100BPM 시작 → 약 91초에 160BPM, 250초 플레이)

값 = 1분 동안의 (일한 시간 합 ÷ 그리는 양 합), 그리는 양 = 프레임의 삼각형 수. 120% 이상이면 한 단계 낮춤.

| 구간 끝(플레이 시작 기준) | 평균 일한 시간 | 처음 1분 대비 |
|---|---|---|
| 약 65초 (기준) | 3.62ms | 100% |
| 약 125초 (160BPM 뒤) | 3.35ms | 93% |
| 약 185초 (160BPM 뒤) | 3.12ms | 90% |

오판 0회.

## 3. 발열 대리 지표

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 메인 화면 엔진 프레임 | 60fps | 30fps |
| 메인 화면 3D 화소 | 배율 3.0 (1179x2556 = 301만, 메인 화면에서도 올라감) | 배율 2.0 (786x1704 = 134만, 자동 품질은 플레이 중에만) |
| 메인 화면 초당 3D 화소 | 1억 8천만 | 4천만 (-78%) |
| 플레이 3D 화소 | 배율 3.0 (301만) | 배율 2.5 (982x2130 = 209만, -31%) |
| 그리는 횟수 / 삼각형 (플레이) | 측정 기능 없음 (구조 같음) | 21 / 약 2만 2천 |
| 브라우저 전체 CPU (메인 화면 / 플레이) | 12.7% / 18.0%, 다시 재면 30.5% / 38.6% | 14.8% / 21.8%, 다시 재면 26.9% / 22.8% |

- CPU 값은 같은 조건에서도 실행마다 2배 넘게 흔들려(헤드리스 휴대폰 흉내는 메인 화면 음악 미리 풀기가 CPU 대부분) 판단에 쓰지 않는다. GPU 시간은 헤드리스에서 못 잼
- 투명 겹침: 기둥 몸통은 뒷면을 잘라 한 기둥당 한 겹(그대로), 넓은 빛 번짐은 배율에 비례해 31% 줄어듦
- 화면 밖·안개 속 물체: MultiMesh 하나로 그리기 횟수가 늘지 않고, 안개 속 장애물은 작아 이득이 작아 그대로
- 상시 작업: 셸 폴링 0.5초 → 2초
