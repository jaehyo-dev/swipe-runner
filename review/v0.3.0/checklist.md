## 박자 정확도 (3분 자동 플레이, 반복 지점 4번 통과, 충돌 0, 장애물 149개)
| 환경 | fps | 도착 프레임의 음악 시간 - 가장 가까운 박 (평균 / 최대) | 벽시계 보간 도착 - 박 격자 (평균 / 최대) |
|---|---|---|---|
| 데스크톱 (CoreAudio, 60fps 제한, 음소거) | 59.9 | 9.11ms / **13.92ms** | 1.23ms / 10.72ms |
| 웹 최종 빌드 (크로미움, Metal GPU) | 59.9 | 8.70ms / **11.50ms** | 0.56ms / 4.74ms |

- 목표(최대 20ms 이하) 통과. 프레임 기준 오차의 대부분은 프레임 간격(16.7ms) 때문이다
- 벽시계 기준은 음악 시계와 독립이라 어긋남을 본다. 웹 3분 기울기 -1.04ms
- 소프트웨어 렌더링(32fps, 프레임 31ms) 웹에서는 프레임 기준 최대 34.86ms: 프레임이 느리면 이 값은 프레임 간격만큼 커진다. 박 격자 자체가 밀리는 것은 아니다. 실제 휴대폰 값은 **미확인**

## 입력 → 재생 명령
같은 프레임. 데스크톱 최대 157µs(49쌍), 웹 최대 4ms(50쌍, 브라우저 타이머 단위가 거침). 녹화 기록은 `events.md`.

## 웹 빌드 직접 확인 (PC 1280x720 방향키, 휴대폰 390x844 터치)
- 첫 입력 전: 오디오 suspended, 재생 0개, 출력 0 → 첫 입력 뒤 running, 음악과 효과음 재생
- 소리 순서(양쪽 같음): 음악, 레인(오른쪽 높게), 레인(왼쪽 낮게), 점프, 착지, 슬라이드, 점프, 슬라이드(공중 아래 스와이프, 착지 없음), 충돌(재생 속도 정확히 1.0), 다시 시작 뒤 레인. 충돌과 다시 시작 사이에는 효과음 없음, 재시작 뒤 음악 계속
- 콘솔 오류·경고 0 (GL 드라이버 성능 메시지 제외)
