# v0.12.1 확인 기록

측정: 맥북 에어, 헤드리스 크롬 + Metal GPU, 393x852 배율 3, 터치(휴대폰 흉내). 도구 `tools/web_probe.mjs`.
실제 아이폰의 GPU·저전력 모드 CPU 제한은 흉내 낼 수 없다 → 최종 확인은 아이폰에서.

## 1. 화질 (계단 현상)

- `zoom_compare.png`: 같은 시드·같은 장면(시작 3.5초, 파란 기둥에 부딪힌 순간)을 3배 확대(최근접). 위에서부터 난간 / 주황 블록·방울 / 방울 이음선·난간·기둥 테두리 / 레인 대시
  - 왼쪽: v0.12.0 (배율 2.0, MSAA 2x) · 가운데: v0.12.1 AUTO 시작값 (배율 2.0 + 가장자리 처리) · 오른쪽: v0.12.1 HIGH (배율 3.0, MSAA 4x + 가장자리 처리)
  - 분홍 블록은 이 장면에 없다 (부딪히기 전까지 나오지 않음)
- `full_compare.png`: 같은 세 장면 전체(축소)
- 결과: 난간·테두리의 계단은 배율 3.0에서 가장 크게 줄어든다(오른쪽). 배율 2.0에서도 방울 이음선이 끊기지 않고 이어진다(가운데·오른쪽 3번째 줄)
- 고친 과정: 처음엔 가장자리를 바닥 색(어두운 색)으로 녹였더니 난간 옆에 검은 계단 테두리가 생겼다 → 지평선 색으로. 이음선은 상자 면마다 녹이니 두 줄로 보였다 → 넓히기·옅게만

## 2. 30fps (아이폰 저전력 모드 흉내)

크롬 rAF를 두 번에 한 번만 넘겨 30Hz, CPU 4배 느리게, `?seed=7&bpm=160&probe=1`(처음부터 160BPM, 측정 중엔 부딪혀도 계속), 시작 뒤 약 25초. 입력은 1.1초마다 ←/→ 18번.

| 경우 | 프레임 | rAF 간격 ms 중앙/99%/최대 | 튀는 프레임 | 게임 프레임 시간 ms 중앙/99% | 속도 흔들림 99% | 박자 오차 ms 99%/최대 | 입력→동작 ms 중앙/최대 |
|---|---|---|---|---|---|---|---|
| v0.12.0 30Hz (100BPM 시작*) | 759 | 33.3 / 33.4 / 50 | 1 | - | - | - | - |
| v0.12.1 30Hz | 759 | 33.3 / 33.4 / 50 | 1 | 33.33 / 33.83 | 7.5% | 14.6 / 17.9 | 13 / 31.4 |
| v0.12.1 16·33ms 섞임 | 1029 | 16.7 / 83.3 / 100.1 | 239 | 20.37 / 73.67 | 7.7% | 18.1 / 24.7 | 9.3 / 48.5 |
| v0.12.1 60Hz | 1519 | 16.7 / 16.8 / 16.8 | 0 | 16.67 / 16.67 | 7.7% | 11.6 / 16.3 | 6.5 / 13.1 |

\* 배포된 v0.12.0은 휴대폰에서 `?bpm`을 쓰면 로딩에서 멈춰(이번에 고친 버그) 100BPM 시작으로 쟀고 `?probe`가 없어 게임 쪽 값이 없다.

- 튀는 프레임 = 간격이 앞 프레임의 1.5배 이상. 섞임은 일부러 무작위로 건너뛴 경우라 많은 것이 정상
- 엔진(Godot 4.7)이 이미 프레임 시간을 화면 갱신 간격에 맞춰 고르게 준다: 30Hz에서 33.33ms 고정. 움직임·카메라·젤리 모션은 모두 이 프레임 시간 기준이라 30Hz에서도 고르다. 그래서 따로 보간 코드를 넣지 않았다
- 속도 흔들림 = 프레임마다 간 거리 ÷ 프레임 시간이 중앙값에서 벗어난 비율. 60Hz·30Hz·섞임 모두 8% 안(음악 시계를 천천히 메우는 상한 MAX_CATCH 8%)
- 박자 오차: 30Hz 최대 17.9ms(≤ 20ms). 섞임은 최대 24.7ms
- 입력→동작: 30Hz 최대 31.4ms < 한 프레임 33.3ms. 섞임 최대 48.5ms는 다음 화면이 그만큼 늦게 온 경우(그 사이 간격 최대 100ms)

## 3. 품질 단계 변화 기록

30Hz 프레임(33.3ms)을 60초 넣었을 때 (판단 계산만, `QualityGuard`):

| | 바뀐 시각 → 단계 |
|---|---|
| v0.12.0 | 8.1초 → 1, 16.3초 → 2, 24.4초 → 3, 32.5초 → 4 (끝까지. 바뀔 때마다 셰이더·MSAA 바뀜 끊김 가능) |
| v0.12.1 | 6.1초 → 1 (30Hz 화면을 알아채 한 번만) |

웹 측정 중 나온 QUALITY 줄:

- 60Hz, CPU 4배: `3초 동안 99% 일하는 시간 7.1ms ≤ 11.7ms → 배율 2.5` (시작 뒤 약 14초), `6.4ms → 배율 3.0` (약 25초)
- 30Hz, CPU 4배: `30Hz 화면: 효과 1단계, 배율 2.0`
- 섞임, CPU 4배: 99% 프레임 50~83ms가 3초 연속 → 효과 1·2·3단계 (실제로 밀리는 경우라 낮추는 것이 맞다)
