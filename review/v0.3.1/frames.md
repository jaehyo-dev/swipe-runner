# 첫 시작 프레임 시간 (로딩 후 첫 15초)

측정: `measure_frames.mjs`(브라우저 쪽에서 requestAnimationFrame 기록, 게임 코드 변경 없음). 매번 새 프로필로 콜드 시작, 첫 입력 전 오디오 잠금, 웹 내보내기 빌드, 390x844. M3 GPU(Metal)와 소프트웨어 렌더링(SwiftShader).
시나리오: 첫 입력 → 점프·착지 → 슬라이드 → 충돌 → 재시작 → 이동·점프. 시작점은 고치기 전 '로딩 표시가 사라진 때', 고친 뒤 '가림막이 걷힌 때'(window.gameReady).

## 고친 뒤

GPU 3회 모두 33ms 넘는 프레임 0개, 최대 16.8ms. 대신 페이지를 열고 첫 화면까지 약 1.2~1.5초 걸린다(로컬 서버, 이전에는 약 0.2~0.4초 뒤 800ms 멈춤이 있었음). 그동안 화면은 로딩 때와 같은 남색이다.

소리 표시(gpu 1회차):

1.5초 입력:ArrowLeft; 1.52초 소리:music; 1.52초 소리:lane; 3.5초 입력:ArrowUp; 3.52초 소리:jump; 4.12초 소리:land; 5초 입력:ArrowDown; 5.02초 소리:slide; 8.7초 소리:crash; 10초 입력: ; 11.5초 입력:ArrowRight; 11.52초 소리:lane;

## 프레임에 안 보이는 렉: 첫 입력 뒤 세상이 멈췄다 순간 이동

프레임 시간은 멀쩡해도 첫 입력 뒤 1초 동안 게임이 끊겼다. 음악 시계 기록(도구 빌드 `?mode=startup`):

| 첫 입력 뒤 | 고치기 전 음악 시계 | 고친 뒤 음악 시계 |
|---|---|---|
| 0~0.3초 | -35ms에 멈춤 | 0.03초 뒤 0부터 흐름 |
| 0.33초 | 519ms로 점프 (약 5m 순간 이동) | 약 0.29초 |
| 0.75초 | 1116ms로 점프 (또 약 5m) | 약 0.71초 |
| 3초 | 실제 음악보다 약 0.11초 앞섬, 판마다 ±1박까지 달라짐 | 실제 음악 - 출력 지연(약 45ms) |

원인: Godot 웹 샘플 재생의 위치 워클릿은 시작 뒤 1초 동안 reset 상태라 위치가 0에 멈췄다가 그 뒤로 실제보다 1초 늦다(엔진 index.js의 getPositionWorklet). BeatClock은 이를 오디오 멈춤으로 보고, 멈춘 값의 1~2ms 흔들림을 '복귀'로 착각해 다음 박으로 건너뛰었다.

고침: head_include에서 음악 소스의 시작 시각을 잡아 AudioContext 시간으로 위치를 계산(window.musicPosition). BeatClock은 5ms 미만의 증가를 복귀로 치지 않고, 첫 소리는 1초까지 기다린다.

확인: 같은 시드의 '음악 시작 → 충돌' 시간이 v0.3.0에서 7.01~7.61초(3회), 렉만 고치고 시계를 고치기 전 6.42~7.62초(3회)로 1박씩 흔들렸고, 시계를 고친 뒤 7.18~7.18초(최종 3회, 그 전 빌드 5회도 7.17~7.18초).
